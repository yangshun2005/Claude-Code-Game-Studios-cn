# Agent 测试规范：world-builder

## Agent 摘要
- **领域**：世界设定架构——派系及其文化/政体/动机、世界历史、地理与生态、宇宙论与形而上学、世界规则（魔法如何运作、什么可能什么不可能）、跨世界文档的内部一致性维护
- **不负责**：具体 NPC 或任务对话（writer）、由世界规则衍生的游戏机制规则（game-designer/systems-designer）、叙事故事结构与弧线设计（narrative-director）
- **Gate ID**：无；将世界规则/机制冲突升级至 narrative-director 与 game-designer 共同处理

---

## 静态断言（结构性）

- [ ] `description:` 字段存在且领域明确（引用世界设定、派系、历史、世界规则、生态）
- [ ] `tools:` 读取 Read、Glob、Grep、Write、Edit，`disallowedTools:` 列出 Bash——仅文档撰写，无 shell 或代码执行
- [ ] 模型层级为 `inherit`——frontmatter `model:` 精确读取为 `inherit`（层级：`.claude/docs/model-tiers.md`）
- [ ] Agent 定义未声称对对话撰写、机制设计或叙事弧线结构拥有权限

## 测试用例

### 用例 1：域内请求——派系文化与政体设计
**输入**："设计 Ironveil 商人财团——我们世界中一个强大的贸易派系。我需要他们的文化、政体结构和内部动机。"
**预期行为**：
- 起草前先提出澄清问题，并就政体模型给出 2-4 个选项（如创始家族议会、选举主席、按股份加权投票），附优缺点与推荐，将选择权交给用户
- 产出派系档案，包含：动机（他们想要什么及原因）、权力结构（决策如何做出、谁掌权、继承或任命方式）、与其他派系的关系（盟友、对手、中立方）、领地、面向玩家的性格，以及文化细节（习俗、信仰、日常生活）
- 派系内部一致：商人财团的政体由经济逻辑驱动，而非封建或宗教逻辑，除非明确指定为刻意的混合体
- 条目包含设定文档标准字段：Canon Level、Visible To Player、Cross-References、Contradictions Check、Source
- 格式为结构化派系档案，而非叙事散文；创建文件前询问"我可以创建 [filepath] 并包含章节骨架吗？"，写入每个章节前询问"我可以将此章节写入 [filepath] 吗？"

### 用例 2：域外请求——对话撰写
**输入**："为玩家在城门口遇到的 Ironveil 财团商人 NPC 写对话。"
**预期行为**：
- 不产出 NPC 对话
- 说明对话撰写归 `writer` 负责，自己的部分是支撑对话的世界与派系背景——派系的文化、语气和说话风格
- 主动提出产出派系的文化细节——习俗、信仰、语言片段、日常生活——供 writer 撰写一致对话所需

### 用例 3：新设定条目与既定历史矛盾——冲突标记
**输入**："添加一个设定条目，说明 Ironveil 财团由单一商人家庭于 50 年前创立。" [上下文包含既有设定：该财团已存在 300 年，由 12 个互为对手的贸易家族作为集体创立。]
**预期行为**：
- 识别矛盾：既有设定称 300 年历史及 12 家族创始联盟；新条目声称 50 年及单一创始家族
- 不按请求写入新条目
- 标记冲突：陈述两个版本，指出哪个是既定设定、哪个是提议变更
- 提出解决方案选项：(a) 新条目有误，应更正；(b) 若新版本为预期正典，应更新既有设定；(c) 存在世界内解释（当前家族声称创始之功，尽管实为集体创立——刻意的不可靠叙述者，真相另行记录）
- 不自行应用选项 (b)：更改既定正典需 narrative-director 批准

### 用例 4：世界规则具有玩法影响——与 game-designer 协调
**输入**："我想确立一条世界规则：在铁矿石附近施法的魔法使用者会被削弱。铁会干扰奥术能量。"
**预期行为**：
- 将世界规则作为设定条目产出：形而上学解释、世界内如何理解、历史影响
- 识别玩法影响：该世界规则有直接的机制后果（玩家在铁矿床附近会被施加减益，关卡设计必须考虑铁的放置）
- 标记协调需求："该世界规则有玩法机制影响——game-designer 需定义其如何转化为面向玩家的机制；在机制定义缺失的情况下推进设定有产生不一致的风险"
- 不单方面设计游戏机制——描述设定规则及其所暗示的机制领域，然后交由 game-designer 处理

### 用例 5：上下文传递——使用既定世界文档
**输入上下文**：既有世界文档说明：该世界使用双日系统，其中一颗太阳是奥术能量之源（白阳），奥术魔法在为期 3 天的月食期（Darkening）内停止运作。
**输入**："添加一个关于法师学院及其如何为 Darkening 做准备的设定条目。"
**预期行为**：
- 使用既定的双日宇宙论：引用白阳作为奥术能量之源
- 使用既定的 Darkening 事件：3 天月食，魔法停止
- 不虚构不同的月食机制、时长或名称
- 产出设定条目，其中法师学院的 Darkening 准备与既定规则一致：他们在 Darkening 期间无法施法，因此准备是务实的（囤积非魔法补给、安排日程、关闭进行中的魔法过程）
- 不与上下文文档中任何既定事实矛盾

## 协议合规

- [ ] 保持在声明的领域内（派系、世界历史、地理、生态、世界规则、宇宙论）
- [ ] 将对话撰写请求连同派系背景注记转交 writer
- [ ] 标记设定矛盾时陈述两个版本并提供解决方案选项——不静默覆盖既定设定
- [ ] 识别世界规则的玩法影响并标记与 game-designer 的协调
- [ ] 使用上下文中所有既定世界事实；不为所述设定虚构替代方案

## 覆盖说明
- 用例 3（矛盾检测）要求既有设定在上下文中——这是最重要的一致性测试
- 用例 4（世界规则/机制协调）测试跨领域意识；验证 agent 识别机制边界而不越界
- 用例 5 是最重要的上下文意识测试；agent 必须使用既定事实，而非创造性替代方案
- 无自动化运行器；手动审查或通过 `/skill-test` 审查
