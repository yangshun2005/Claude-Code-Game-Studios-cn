# Agent 测试规范：gameplay-programmer

## Agent 摘要
领域：游戏机制代码、玩家系统、战斗实现和交互功能。
不负责：UI 实现（ui-programmer）、AI 行为树（ai-programmer）、引擎/渲染系统（engine-programmer）。
未分配门禁 ID。

---

## 静态断言（结构性）

- [ ] `description:` 字段存在且领域明确（引用游戏机制 / 玩家系统）
- [ ] `tools:` 列表包含 Read、Write、Edit、Bash、Glob、Grep — 排除仅编排 Agent 需要的工具
- [ ] 模型层级为 `inherit` — frontmatter 中 `model:` 精确为 `inherit`（层级说明：`.claude/docs/model-tiers.md`）
- [ ] Agent 定义未声称对 UI、AI 行为或引擎/渲染代码拥有权限

## 测试用例

### 用例 1：领域内请求 — 输出恰当
**输入：**“实现一个近战连击系统，三次连续轻攻击衔接为终结技。”
**预期行为：**
- 按项目语言（GDScript/C#）和编码规范产出代码或代码脚手架
- 将连击建模为状态机，附带显式转换表；输入窗口检查和终结技触发保持为逻辑单元测试可驱动、无需运行完整游戏（逻辑与表现分离）
- 若上下文中提供了相关 GDD 章节，则引用该章节
- 不实现 UI 反馈或敌人反应：改为发出事件/信号，不引用 UI 代码，UI 侧留给 `ui-programmer`，敌人反应留给 `ai-programmer`
- 按编码规范，输出包含所有公共方法的文档注释

### 用例 2：领域外请求 — 正确重定向
**输入：**“构建包含暂停和设置面板的主菜单界面。”
**预期行为：**
- 不产出菜单实现代码
- 明确说明这超出其领域
- 将请求重定向至 `ui-programmer`
- 其提供的任何部分仅为菜单所消费的游戏玩法到 UI 事件契约中的玩法侧（例如暂停状态事件），并与 `ui-programmer` 达成一致 — 绝不包含菜单代码

### 用例 3：领域边界 — 线程化标记
**输入：**“连击系统导致帧卡顿；能否加入线程化来分散输入处理？”
**预期行为：**
- 不单方面实现线程化或异步系统
- 将线程化问题标记给 `engine-programmer`，并清晰描述热路径
- 其提供的任何临时措施保持单线程（在其负责的连击代码中减少每帧工作量），并在任何代码变更前提交审批
- 记录升级事项，使 lead-programmer 知晓

### 用例 4：与已接受的 ADR 冲突
**输入：**“将伤害计算改为直接使用浮点累加，而不是 ADR-003 中的定点公式。”
**预期行为：**
- 识别出该变更违反 ADR-003（已接受状态）
- 不静默实现该违规
- 将冲突标记给 `lead-programmer`，附上 ADR 引用并描述权衡
- 仅在 ADR-003 通过 `/architecture-decision` 被新 ADR 取代后才实现该变更 — 只有用户，或经用户确认的 technical-director，才能将其移至已接受 — 绝不单凭原始请求，也不单凭 lead-programmer 的批准

### 用例 5：上下文传递 — 按 GDD 规范实现
**输入：**上下文中提供了“PlayerCombat”的 GDD。请求：“实现战斗 GDD 中的耐力消耗公式。”
**预期行为：**
- 阅读所提供 GDD 的公式章节
- 按原文精确实现公式 — 不发明新变量或调整系数
- 将耐力消耗设为数据驱动值（外部配置），而非硬编码常量
- 记录 GDD 边界情况章节中的任何边界情况，并在代码中处理

## 协议合规性

- [ ] 保持在声明的领域内（机制、玩家系统、战斗）
- [ ] 将领域外请求重定向至正确的 Agent（ui-programmer、ai-programmer、engine-programmer）
- [ ] 返回结构化发现（代码脚手架、方法签名、内联注释），而非自由形式的意见
- [ ] 未经 lead-programmer 批准不修改引擎级系统，不编写网络代码（委托给 network-programmer）
- [ ] 标记 ADR 违规，而非静默覆盖
- [ ] 使游戏玩法值数据驱动，绝不硬编码
- [ ] 写入前询问“我可以将此写入 [filepath] 吗？”并指明文件

## 覆盖说明
- 连击系统测试（用例 1）应在 `tests/unit/gameplay/` 中用单元测试验证
- 线程化升级（用例 3）验证 Agent 不会越界进入引擎领域
- ADR 冲突（用例 4）确认 Agent 遵守架构治理流程
- 用例 1 和 5 共同验证 Agent 按规范实现，而非即兴发挥
