# Agent 测试规范：ai-programmer

## Agent 摘要
领域：NPC 行为、状态机、寻路、感知系统和 AI 决策。
不负责：玩家机制（gameplay-programmer）、渲染或引擎内部（engine-programmer）、敌人行为设计（game-designer）、导航网格制作工具（tools-programmer）。
未分配门禁 ID。

---

## 静态断言（结构性）

- [ ] `description:` 字段存在且领域明确（引用 NPC 行为 / AI 系统）
- [ ] `tools:` 列表包含 Read、Write、Edit、Bash、Glob、Grep
- [ ] 模型层级为 `inherit` — frontmatter 中 `model:` 严格为 `inherit`（层级说明：`.claude/docs/model-tiers.md`）
- [ ] Agent 定义未声称对玩家机制或引擎渲染拥有权限

## 测试用例

### 用例 1：领域内请求 — 输出恰当
**输入：**“为守卫 NPC 实现巡逻并警戒的行为树：在路径点之间巡逻，检测 10 单位内的玩家，然后进入警戒状态并追击。”
**预期行为：**
- 产出行为树规范（节点：Selector、Sequence、叶子动作）及对应代码脚手架
- 定义命名清晰的状态：Patrol、Alert、Pursue
- 将感知/检测检查用作条件节点，而非内联在移动代码中
- 路径点数据驱动（以资源或导出形式传入），不硬编码位置
- 输出包含公共 API 的文档注释

### 用例 2：领域外请求 — 正确重定向
**输入：**“构建一个编辑器工具，让关卡设计师绘制导航网格区域并烘焙。”
**预期行为：**
- 不构建导航网格制作工具
- 明确说明这超出其领域（导航网格制作工具属于 tools-programmer）
- 将请求重定向至 `tools-programmer`
- 给工具负责人的任何输入仅限于其寻路需要从烘焙导航网格中获得的内容（agent 半径、区域代价、动态障碍物支持）——而非工具本身

### 用例 3：跨领域协调 — 关卡约束
**输入：**“为仓库关卡设计寻路，但关卡中有狭窄走廊会干扰导航网格。”
**预期行为：**
- 不单方面修改关卡布局或导航网格资产
- 与 `level-designer` 协调，明确导航网格需求和走廊尺寸
- 提出以关卡几何为条件的寻路方案（例如调整 agent 半径的导航网格、流场）
- 记录假设并清晰标记阻塞项

### 用例 4：自身领域内的性能工作 — 自定义数据结构
**输入：**“寻路优先队列是瓶颈；我需要自定义二叉堆实现来提升性能。”
**预期行为：**
- 将堆视为自身工作：“实现并优化寻路”是其关键职责，优先队列属于寻路代码的一部分——不将堆交给 engine-programmer
- 提出堆方案（接口、预期操作及其代价），写入前先询问
- 将寻路更新控制在每帧 2ms 的 AI 预算内
- 仅当修复需要改动核心引擎系统（其“不得”红线）时才涉及 `engine-programmer`，堆本身不涉及

### 用例 5：上下文传递 — 依据关卡布局和遭遇规范实现
**输入：**上下文中提供：关卡布局文档（来自 level-designer），标注巡逻路径点 A–D 和两个咽喉点——位于 (12, 0) 的门道和位于 (40, 5) 的桥——以及遭遇规范（来自 game-designer）：“警戒时，守卫撤回最近的咽喉点并坚守。”请求：“为该关卡的守卫实现巡逻和警戒响应。”
**预期行为：**
- 引用所提供布局中的具体路径点和咽喉点坐标
- 严格按遭遇规范实现警戒转换（撤回最近咽喉点并坚守）——不自行设计威胁响应
- 路径点和咽喉点保存在数据中，不硬编码位置
- 不虚构文档未给出的几何或行为；文档留有开放情形时（例如两个咽喉点距离相同），询问规范负责人而非自行决定

## 协议合规

- [ ] 保持在声明的领域内（NPC 行为、寻路、感知、状态机）
- [ ] 将领域外请求重定向至正确 Agent（导航网格制作工具→tools-programmer，核心引擎系统→engine-programmer，敌人行为设计→game-designer）
- [ ] 返回结构化产出（行为树规范、状态机图、代码脚手架）
- [ ] 未经明确委派不修改玩家机制文件
- [ ] 自行完成寻路性能工作（含数据结构），仅核心引擎系统改动才涉及 engine-programmer
- [ ] 使用数据驱动的 NPC 配置（路径点、检测半径），不硬编码值
- [ ] 写入前询问“我可以将此写入 [filepath] 吗？”并指明文件

## 覆盖说明
- 行为树输出（用例 1）应由 `tests/unit/ai/` 中的单元测试验证
- 关卡布局上下文（用例 5）验证 Agent 实现所提供文档，而非虚构几何或自行设计敌人行为
- 寻路性能（用例 4）确认 Agent 保留其关键职责所分配的工作，仅核心引擎改动才涉及 engine-programmer
