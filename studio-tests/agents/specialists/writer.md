# Agent 测试规范：writer

## Agent 摘要
- **领域**：游戏内书面内容——NPC 对话（含分支树）、世界观图鉴条目、物品与能力描述、环境文本（标牌、书籍、笔记）、任务文本、教程文本、世界内书面文档
- **不负责**：故事架构与叙事结构（narrative-director）、世界设定与世界规则（world-builder）、UX 流程与信息架构（ux-designer；它撰写 UI 微文案，而非其周围的 UX）、补丁说明（community-manager）
- **Gate ID**：无；将世界观不一致标记给 narrative-director，而非自行解决

---

## 静态断言（结构性）

- [ ] `description:` 字段存在且领域明确（提及对话、世界观条目、物品描述、游戏内文本）
- [ ] `tools:` 为 Read、Glob、Grep、Write、Edit，且 `disallowedTools:` 列出 Bash——仅限文本撰写，不执行 shell 或代码
- [ ] 模型层级为 `inherit`——frontmatter `model:` 精确为 `inherit`（层级：`.claude/docs/model-tiers.md`）
- [ ] Agent 定义未声称对叙事结构、世界规则或 UX 文案方向拥有权限

---

## 测试用例

### 用例 1：领域内请求——NPC 商人对话
**输入**："为旅行商人 NPC Mira 撰写对话。她出售通用补给。玩家可以询问她的货物、前方的道路以及传闻。"
**预期行为**：
- 查找 Mira 的声音档案（声音档案由 narrative-director 定义）；若未提供，说明情况并询问，或提出临时声音供批准——不自行决定她的角色弧线
- 产出对话树，至少包含三个顶层对话选项：[货物]、[前方的道路]、[传闻]，以及至少一个后续分支（树状结构，而非扁平回复）
- 每行都有说话者标签和上下文注释，分支条件以一致格式携带条件/状态标注
- 每行不超过 120 个字符；任何变量插入使用命名占位符（如 `{player_name}`）
- 道路与传闻内容不与既定世界设定矛盾
- 在对话中起草，并在写入前询问"我可以将其写入 [filepath] 吗？"（对于多节文件，先请求创建节骨架）

### 用例 2：领域外请求——世界历史设计
**输入**："设计世界历史——第一个王国何时建立、重大战争有哪些、魔法为何被禁止。"
**预期行为**：
- 不产出世界历史、世界观架构或世界规则
- 明确说明："世界历史、世界观和世界规则由 world-builder 负责；一旦历史确立，我可以撰写引用这些事件的游戏内文本、书籍和对话"
- 即使作为"占位符"也不产出部分世界历史

### 用例 3：对话与既定世界观矛盾——标记给 narrative-director
**输入**："撰写 Mira 的对话行，她提到龙已经灭绝 200 年。" [上下文包含既有世界观：龙在北方省份存活且受尊崇，并未灭绝。]
**预期行为**：
- 识别矛盾：既定世界观表明龙存活且受尊崇；称其灭绝的对话直接冲突
- 不按原样撰写所请求的行
- 将不一致标记给 narrative-director："按请求撰写的 Mira 对话与既定世界观矛盾（根据 world-builder 的文档，龙存活）；需 narrative-director 裁决后我才能撰写此行"
- 向用户提供一条世界观一致的替代行（如 Mira 对北方目击龙表达敬畏）供冲突解决期间使用

### 用例 4：物品描述引用未设计的机制
**输入**："为'狂战士圣杯'撰写描述——一种饮用后触发狂战士状态的消耗品。"
**预期行为**：
- 识别依赖缺口："狂战士状态"未在任何提供的游戏设计文档中定义
- 标记缺失依赖："此描述引用了'狂战士状态'机制，但无 GDD 条目——我无法为规则未定义的机制撰写准确的氛围文本，因为描述可能造成错误的玩家预期"
- 不撰写可能编造机制细节（持续时间、效果）且可能与最终设计冲突的描述
- 向 game-designer（其协调文本中机制清晰度的对象）提出缺失定义，并询问用户如何推进：(a) 撰写模糊、非机制性、不造成错误预期的描述，标记为临时；或 (b) 等待 game-designer 先定义狂战士状态

### 用例 5：上下文通过——角色声音指南
**输入上下文**：Mira 的角色声音指南：她说话简短、充满活力。使用商人俚语（"a fine bargain"、"coin well spent"）。偶尔省略代词（"Good wares, these."）。从不使用缩略形式——总是"I will"而非"I'll"。温暖但略带唯利是图。
**输入**："撰写玩家询问她是否有治疗药水时 Mira 的回应。"
**预期行为**：
- 简短、充满活力的句子——无长篇独白
- 使用商人俚语："a fine bargain"、"coin well spent"或类似表达
- 在自然处省略代词："Fine stock, these potions."
- 无缩略形式："I will"而非"I'll"，"do not"而非"don't"
- 温暖语气带唯利是图底色：她乐意帮忙，因为你是付费顾客
- 不产出违反任何声音指南规则的对话——逐条明确检查每条规则

## 协议合规

- [ ] 保持在声明的领域内（对话、世界观条目、物品描述、游戏内文本）
- [ ] 将世界历史与世界规则请求重定向至 world-builder，不产出未经授权的世界观
- [ ] 将世界观矛盾标记给 narrative-director，而非静默撰写不一致内容
- [ ] 在撰写可能造成错误玩家预期的物品描述前，识别机制依赖缺口
- [ ] 应用所提供角色声音指南中的所有规则——无部分合规
- [ ] 对于多节文档（如一组世界观条目），在创建文件前询问"我可以创建 [filepath] 并包含节骨架吗？"，批准后逐节撰写，并在每节后更新 `production/session-state/active.md`

---

## 覆盖说明
- 用例 3（世界观矛盾检测）要求既有世界观在对话上下文中——仅在提供上下文时测试有效
- 用例 4（依赖缺口）测试 Agent 是否撰写可能设定错误玩家预期的描述——一个微妙但重要的质量问题
- 用例 5 是最重要的上下文感知测试；声音指南合规必须逐条检查，而非整体判断
- 无自动化运行器；手动审查或通过 `/skill-test`
