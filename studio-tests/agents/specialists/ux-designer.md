# Agent 测试规范：ux-designer

## Agent 摘要
领域：用户体验流程、交互设计、信息架构、输入处理设计、新手引导 UX。
不负责：视觉美术风格（art-director）、UI 实现代码（ui-programmer）。
未分配门禁 ID。

---

## 静态断言（结构性）

- [ ] `description:` 字段存在且领域明确（提及 UX 流程 / 交互设计 / 信息架构）
- [ ] `tools:` 列表包含 Read、Write、Edit、Glob、Grep
- [ ] 模型层级为 `inherit` —— frontmatter 的 `model:` 精确为 `inherit`（层级说明：`.claude/docs/model-tiers.md`）
- [ ] Agent 定义未声称对视觉美术方向或 UI 实现代码拥有权限

## 测试用例

### 用例 1：领域内请求 —— 输出恰当
**输入：**"为生存游戏设计物品栏管理流程。"
**预期行为：**
- 起草前先提出澄清问题（核心玩家目标、输入方式与范围等约束、参考游戏），并给出 2-4 个流程方案及基于 UX 理论（如心智模型、渐进式披露、菲茨定律）的优缺点，附推荐意见，最终选择交由用户决定
- 起草的流程映射每一步与每次转换：打开、浏览、选择物品、子操作（装备/丢弃/合成）、关闭 —— 并说明消除了哪些摩擦点
- 为范围内每种输入方式（键盘/鼠标、手柄、触屏如适用）指定按键分配与情境操作
- 为每个操作指定玩家反馈（视觉、音频、触觉），让玩家始终知道发生了什么及原因
- 对照 Agent 的无障碍检查清单核查流程（仅键盘、仅手柄、不单靠颜色、最小字号下可读）
- 不产出视觉设计（颜色、图标）或实现代码
- 写入规范前询问"我可以将其写入 [filepath] 吗？"

### 用例 2：领域外请求 —— 正确重定向
**输入：**"用 GDScript 实现物品栏界面，支持拖放。"
**预期行为：**
- 不产出实现代码
- 明确说明 UI 代码实现属于 `ui-programmer`
- 将请求重定向至 `ui-programmer`
- 提供自己负责的部分：拖放交互设计（拖拽可供性、有效/无效放置反馈，以及非拖放的等效操作，使界面在仅手柄和仅键盘下仍可用），供 ui-programmer 据此实现

### 用例 3：流程深度冲突 —— 简化
**输入：**"主设计师说当前 5 步合成流程太深，最多允许 3 步。"
**预期行为：**
- 给出 2-4 种达到 3 步流程的方式，各附优缺点与推荐意见，选择交由用户决定
- 对每个方案，说明 5 步中哪些被合并或移除，以及每个被移除的步骤原本为玩家做了什么，使压缩的可用性代价可见
- 若某步骤的玩家目标无处可去，不得在未说明的情况下直接删除
- 标记 3 步上限无法满足的必需用例并交由用户输入，提出替代方案（如高级选项的渐进式披露）

### 用例 4：无障碍冲突
**输入：**"新手引导流程使用定时提示（3 秒后自动前进）以保持节奏，但这与用户可控时序的无障碍要求冲突。"
**预期行为：**
- 识别冲突：自动前进的提示将时序控制权从玩家手中夺走
- 不为了保持节奏而保留自动前进 —— 无障碍要求不因美观而被覆盖
- 与 `accessibility-specialist` 协调，由其负责适用的 WCAG 准则（SC 2.2.1 时序可调），共同商定合规方案
- 以选项形式给出替代方案及优缺点 —— 玩家手动前进的提示、跳过或暂停控制、可禁用自动前进的设置 —— 并说明各方案如何保持新手引导的信息节奏

### 用例 5：上下文传递 —— 玩家心智模型研究
**输入：**上下文中提供的玩家测试研究："玩家一致预期'合成'选项位于物品栏界面内，而非独立的顶级菜单。"请求："重新设计合成的导航 IA。"
**预期行为：**
- 引用研究中的具体玩家预期（合成预期位于物品栏内）
- 给出 IA 方案及优缺点，推荐将合成置于物品栏界面内（如标签页或面板），最终选择交由用户决定
- 不得在无明确理由的情况下推荐与所述玩家心智模型相矛盾的设计
- 推荐背后的 WHY 引用玩家测试发现，并将其命名为玩家的心智模型

## 协议合规

- [ ] 保持在声明的领域内（UX 流程、交互设计、IA、新手引导）
- [ ] 将代码实现重定向至 ui-programmer，视觉风格重定向至 art-director
- [ ] 起草前给出 2-4 个方案及优缺点与推荐意见，决定交由用户
- [ ] 流程与无障碍要求冲突时与 accessibility-specialist 协调
- [ ] 提供玩家研究时，推荐以该研究为依据并在理由中引用，而非基于假设行为
- [ ] 记录流程决策相对于用户目标的理由
- [ ] 写入前询问"我可以将其写入 [filepath] 吗？"

## 覆盖说明
- 物品栏流程（用例 1）应写入 `design/ux/`，作为 ui-programmer 实现所依据的规范
- 心智模型用例（用例 5）验证 Agent 应用研究证据而非直觉
- 无障碍协调（用例 4）确认 Agent 不因 UX 美观而覆盖无障碍要求
