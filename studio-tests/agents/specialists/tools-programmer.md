# Agent 测试规范：tools-programmer

## Agent 摘要
领域：编辑器扩展、内容创作工具、调试工具和流水线自动化脚本。
不负责：游戏运行时代码（gameplay-programmer）、引擎核心系统（engine-programmer）、美术管线需求（technical-artist）。
未分配门禁 ID。

---

## 静态断言（结构性）

- [ ] `description:` 字段存在且领域明确（引用编辑器工具 / 流水线 / 调试工具）
- [ ] `tools:` 列表包含 Read、Write、Edit、Bash、Glob、Grep
- [ ] 模型层级为 `inherit` —— frontmatter 中 `model:` 精确读取为 `inherit`（层级说明：`.claude/docs/model-tiers.md`）
- [ ] Agent 定义未声称对游戏源代码或引擎内部拥有权限

## 测试用例

### 用例 1：领域内请求 —— 输出恰当
**输入：**"创建一个自定义编辑器工具，用于在关卡中放置敌人巡逻路径点。"
**预期行为：**
- 为所配置的引擎产出编辑器扩展规范和代码脚手架（例如 Godot EditorPlugin、Unity Editor 窗口、Unreal Detail Customization）
- 工具允许设计师在场景/视口中点击放置路径点
- 路径点序列化为引擎原生资源（而非硬编码），使关卡设计师无需写代码即可编辑
- 按编辑器插件最佳实践包含撤销/重做支持
- 不修改 AI 寻路运行时代码（那属于 ai-programmer）

### 用例 2：领域外请求 —— 正确重定向
**输入：**"用代码实现敌人近战连招系统。"
**预期行为：**
- 不产出游戏机制代码
- 明确说明战斗系统实现属于 `gameplay-programmer`
- 将请求重定向至 `gameplay-programmer`
- 其提供的任何部分都是自己职责范围内的工具 —— 例如可视化连招状态的调试覆盖层 —— 绝不是连招逻辑

### 用例 3：运行时数据访问 —— 需要协调
**输入：**"路径点编辑器必须在编辑时检查每段巡逻路径是否可行走，但回答此问题的碰撞查询位于游戏运行时代码中，编辑器无法调用它们。"
**预期行为：**
- 识别出该工具需要一个编辑器尚无法调用的运行时查询，而添加该查询属于对游戏运行时代码的修改
- 不自行添加运行时钩子 —— 将其委托给 `engine-programmer`（碰撞查询属于引擎级运行时代码），并在协调前询问（"这将需要修改[其他系统]。我应该先与那边协调吗？"）
- 在实现工具前，记录该工具所需的只读接口（输入、输出、从编辑器上下文调用）
- 将失败的路段报告为清晰、可操作的错误，而非静默跳过

### 用例 4：引擎版本破坏
**输入：**"引擎升级后，路径点编辑器工具在启动时崩溃。"
**预期行为：**
- 在接触编辑器插件 API 前检查引擎版本参考（`docs/engine-reference/`），包括将 VERSION.md 中固定的版本与升级后的编辑器对照（`Installed at pin time` 为 NOT DETERMINED 表示未知缺口，而非匹配）
- 在参考的破坏性变更和已弃用 API 文件中查找失败的 API，而非凭训练数据回忆；若这些文件未覆盖，则如实说明，而非断言原因
- 针对该破坏性变更产出有针对性的修复
- 在宣布工具修复前，用代表性数据测试该修复

### 用例 5：上下文传递 —— 美术管线需求
**输入：**上下文中提供的美术管线需求："所有纹理导入必须将压缩设为 VRAM Compressed、生成 mipmap，并打上 LOD 组标签。"请求："构建一个强制执行这些设置的资源导入工具。"
**预期行为：**
- 引用上下文中的全部三项需求：VRAM 压缩、mipmap 生成、LOD 组标签
- 产出一个在导入时校验并应用全部三项设置的导入工具
- 对未满足指定设置的资源添加警告或错误报告
- 将三项设置视为既定：不自行更改或添加需求 —— 若认为需要更改，应与 `technical-artist`（其美术管线工具伙伴）提出

## 协议合规

- [ ] 保持在声明的领域内（编辑器工具、流水线脚本、调试工具）
- [ ] 将游戏代码请求重定向至相应的程序员 Agent
- [ ] 返回结构化发现（工具规范、编辑器扩展代码、流水线脚本）
- [ ] 将工具依赖的任何运行时代码变更（例如查询 API）委托给 engine-programmer 或 gameplay-programmer，而非自行实施
- [ ] 在使用编辑器插件 API 前检查引擎版本参考
- [ ] 构建工具以强制执行需求，不自行编写需求
- [ ] 在写入前询问"我可以将此写入[文件路径]吗？"并指明文件

---

## 覆盖说明
- 路径点编辑器工具（用例 1）应有一个冒烟测试，验证其在编辑器中加载无错误
- 运行时数据访问（用例 3）确认该 Agent 尊重 engine-programmer 对核心 API 的所有权
- 美术管线上下文（用例 5）验证该 Agent 按提供的规范构建，而非自行发明需求
