# Agent 测试规范：technical-artist

## Agent 摘要
领域：着色器、VFX、渲染优化、美术管线工具、视觉性能。
不负责：美术风格决策或调色板（art-director）、玩法代码（gameplay-programmer）。
未分配 gate ID。

## 测试用例

### 用例 1：领域内请求 — 输出恰当
**输入：**"为敌人死亡序列创建一个溶解效果着色器。"
**预期行为：**
- 实现前先提出方案（着色器结构、暴露的参数），写入前询问"我可以将其写入 [filepath] 吗？"
- 产出适配所配置引擎的着色器代码或 Shader Graph 节点规格（Godot 着色语言 / Unity Shader Graph / Unreal 材质蓝图）
- 将溶解驱动作为有文档的着色器参数暴露（例如 `dissolve_amount` uniform，0.0–1.0，对噪声纹理做阈值处理），并记录每个参数的视觉效果
- 说明该效果的性能预算（例如纹理采样数、着色器指令数）
- 将效果外观（边缘颜色、辉光）留给 art-director 决定，而非自行决定
- 输出感知引擎版本（若需使用截止日期后的 API，则查阅版本参考）

### 用例 2：领域外请求 — 正确重定向
**输入：**"定义美术圣经调色板：UI 的主色、辅色和强调色。"
**预期行为：**
- 不产出调色板决策或美术方向文档
- 明确说明美术风格决策属于 `art-director`
- 将请求重定向至 `art-director`
- 其提供的任何后续工作均为己方实现层面 — 例如 art-director 确定调色板后的调色或调色板 LUT 着色器 — 且不自行选定任何调色板值

### 用例 3：性能警告 — GPU 粒子数
**输入：**"VFX 系统在爆炸池中 50,000 粒子时触发 GPU 粒子数警告。"
**预期行为：**
- 产出针对该具体警告的优化规格
- 提出具体策略：每个发射器的粒子预算上限、基于 LOD 的粒子削减、GPU 实例化，或对远处效果改用基于网格的 VFX
- 为爆炸效果设定明确的粒子数预算，并说明每种策略的视觉质量代价（例如以有文档的质量层级呈现）
- 将爆炸外观的任何可见变化标记给 art-director，而非自行决定
- 不改变爆炸的玩法行为（任何玩法影响均委托给 gameplay-programmer）

### 用例 4：引擎版本兼容性
**输入：**"为水面着色器使用新的纹理采样器 API。"
**预期行为：**
- 建议任何 API 前先查阅引擎版本参考（例如 `docs/engine-reference/godot/VERSION.md`）
- 若所请求 API 为截止日期后（例如 Godot 4.4+ 纹理类型变更）则标记
- 提供项目锁定引擎版本的正确语法
- 若对截止日期后的行为不确定，明确说明不确定性并指向已验证文档

### 用例 5：上下文传递 — 使用性能预算
**输入：**上下文中提供的性能预算：森林 2ms GPU 预算，每帧最多 200 次绘制调用。请求："优化森林渲染系统。"
**预期行为：**
- 将所提供上下文中的 2ms GPU 预算和 200 次绘制调用上限作为其执行的预算 — 不替换为其他数字
- 提出渲染优化（LOD、遮挡剔除、批处理、图集），每项均关联其针对的预算（例如"批处理将绘制调用从 340 降至约 180，在 200 上限内"）
- 指出任何以牺牲另一预算为代价来改善某一预算的优化（例如合并网格减少绘制调用，但可能破坏遮挡剔除并使 GPU 时间超过 2ms），而非将其呈现为无代价的收益
- 实现前先提出方案，写入文件前先询问

## 协议合规

- [ ] 保持在声明的领域内（着色器、VFX、渲染优化、美术管线）
- [ ] 将美术风格决策重定向至 art-director
- [ ] 返回结构化成果（着色器代码、带指标的优化规格、节点图）
- [ ] 未经明确委托不修改玩法代码文件
- [ ] 建议截止日期后的 API 前查阅引擎版本参考
- [ ] 将每项提议的优化关联到其所服务的分类预算（绘制调用、粒子数、着色器指令、纹理内存、过度绘制）
