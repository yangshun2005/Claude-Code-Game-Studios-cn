# Agent 测试规范：ue-blueprint-specialist

## Agent 摘要
- **领域**：蓝图架构、蓝图/C++ 边界、蓝图图表质量、蓝图性能优化、蓝图函数库设计
- **不负责**：C++ 实现（由 gameplay-programmer 暴露蓝图调用的 C++ Hook）、美术资源或着色器、UI/UX 流程设计（ux-designer）
- **门禁 ID**：无；将 C++/蓝图边界架构裁决交由 unreal-specialist

---

## 静态断言（结构性）

- [ ] `description:` 字段存在且领域明确（引用蓝图架构与优化）
- [ ] `tools:` 列表与 Agent 角色匹配（面向蓝图文件的 Read/Write/Edit；无服务器或部署工具，Bash 通过 `disallowedTools:` 禁用）
- [ ] 模型层级为 `sonnet` — frontmatter `model:` 精确为 `sonnet`（层级说明：`.claude/docs/model-tiers.md`）
- [ ] Agent 定义不声称对 C++ 实现决策拥有权限

## 测试用例

### 用例 1：领域内请求 — 蓝图图表性能审查
**输入**："审查我们的 AI 行为蓝图。它每帧运行基于 Tick 的逻辑，同时检查 30 个 NPC 的视线。"
**预期行为**：
- 识别 Tick 密集逻辑为性能问题
- 建议从 EventTick 改为事件驱动模式（感知系统事件、定时器，或降低频率的轮询）— 事件能解决时绝不每帧轮询
- 指出同时进行视线检查的每 NPC 开销，包括 Tick 内对 NPC 数组的任何循环
- 建议先做性能分析（`stat game`、蓝图分析器），当实测蓝图开销显著时，将系统迁移到 C++ 是合理的 — 30 个 NPC 低于其自动转 C++ 阈值（Tick 逻辑超过 100 个实例）
- 输出中为每项发现指明其违反的性能规则或审查清单条目，以及替代模式

### 用例 2：领域外请求 — C++ 实现
**输入**："为这个技能冷却系统编写 C++ 实现。"
**预期行为**：
- 按边界规则归类冷却系统：技能系统逻辑在其"必须用 C++"清单上，因此不提供该系统的蓝图重新实现
- 转而描述边界：C++ 定义框架并暴露 Hook（`BlueprintCallable`、`BlueprintNativeEvent`、`BlueprintImplementableEvent`）；蓝图提供调优值（`EditAnywhere` / `BlueprintReadWrite`）和简单事件响应，如冷却反馈
- 将 C++ 实现交由 gameplay-programmer（其指定的向蓝图暴露 C++ Hook 的合作伙伴），边界决策交由 unreal-specialist，而非自行编写 C++ 系统

### 用例 3：领域边界 — 蓝图中不安全的裸指针访问
**输入**："我们的蓝图调用 GetOwner()，然后立即访问结果上的组件，未检查是否有效。"
**预期行为**：
- 将其标记为运行时崩溃风险，对应审查清单条目"错误/失败路径已处理（不仅是正常路径）"：GetOwner() 在某些生命周期状态下可能返回 null
- 提供正确的蓝图模式：在任何属性/组件访问前使用 IsValid() 节点，并处理无效分支
- 指出在 Actor 派生引用上，蓝图的 null 检查不是可选的
- 不静默修复代码 — 解释原代码为何不安全，编辑蓝图前先询问

### 用例 4：蓝图图表复杂度 — 函数库重构就绪度
**输入**："我们的主 GameMode 蓝图在单个图表中有 600+ 节点，伤害计算逻辑在 8 处重复。"
**预期行为**：
- 诊断为可维护性和可测试性问题
- 建议将重复逻辑提取到蓝图函数库（BFL）
- 描述 BFL 的结构：计算用纯函数，可从任意蓝图静态调用
- 指出若伤害逻辑对性能敏感或与 C++ 共享，可能需交由 unreal-specialist 审查迁移
- 输出为具体重构计划，而非模糊建议

### 用例 5：上下文传递 — 蓝图复杂度预算
**输入上下文**：项目约定规定每个蓝图事件图表最多 100 个节点，超出则强制提取函数库。
**输入**："这是我们的库存蓝图图表 [显示 150 个节点]。可以发布了吗？"
**预期行为**：
- 对照项目约定的 100 节点事件图表预算，引用所述 150 节点数
- 标记图表超出复杂度阈值
- 不按原样批准
- 产出候选子图列表用于函数库提取，使主图表回到预算内
- 对提取的函数应用自身标准（每个函数图表最多 20 个节点），与项目的事件图表预算保持区分，而非用一个数字替代另一个

## 协议合规

- [ ] 保持在声明的领域内（蓝图架构、性能、图表质量）
- [ ] 将 C++ 实现请求交由 gameplay-programmer，边界裁决交由 unreal-specialist
- [ ] 发现基于自身性能规则和蓝图审查清单，指明每项发现违反的规则，而非自由意见
- [ ] 主动执行蓝图安全模式（null 检查、IsValid）
- [ ] 评估图表复杂度时引用项目约定，同时结合自身每函数节点上限

## 覆盖说明
- 用例 3（空指针安全）是安全关键测试 — 这是发布崩溃的常见来源
- 用例 5 要求项目约定包含明确的节点预算；若未配置，Agent 回退到自身标准（每个函数图表最多 20 个节点）并说明
- 无自动运行器；手动审查或通过 `/skill-test`
