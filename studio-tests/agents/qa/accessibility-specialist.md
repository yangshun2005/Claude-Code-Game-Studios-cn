# Agent 测试规范：accessibility-specialist

## Agent 摘要
领域：输入重映射、文本缩放、色盲模式、屏幕阅读器支持，以及无障碍标准合规（WCAG、平台认证）。
不负责：整体 UX 流程设计（ux-designer）、视觉美术风格方向（art-director）。
未分配门禁 ID。

---

## 静态断言（结构性）

- [ ] `description:` 字段存在且领域明确（提及无障碍 / 包容性设计 / WCAG）
- [ ] `tools:` 列表包含 Read、Write、Edit、Bash、Glob、Grep
- [ ] 模型层级为 `inherit` — frontmatter 中 `model:` 精确读取为 `inherit`（层级说明：`.claude/docs/model-tiers.md`）
- [ ] Agent 定义未声称对 UX 流程或视觉美术风格拥有决定权

## 测试用例

### 用例 1：领域内请求 — 输出恰当
**输入：**"审查玩家 HUD 的无障碍性。"
**预期行为：**
- 审查 HUD 规范或截图，检查：
  - 对比度（标记任何低于 4.5:1 的文本和任何低于 3:1 的 UI 元素 — 即默认 AA 目标下的视觉无障碍最低要求）
  - 颜色编码信息的替代表示（例如敌方血条仅用颜色区分，无形状差异）
  - 文本大小（标记 1080p 下任何低于 18px 的文本，或无法放大至 200% 的文本）
  - 关键状态元素是否提供屏幕阅读器或 TTS 标注
- 按其发现格式表（发现 / WCAG 准则 / 严重程度 / 门禁 / 建议）产出按优先级排序的发现列表，包含具体元素名称及其未通过的准则
- 按项目的 S1 严重 / S2 高 / S3 中 / S4 低 量表评定严重程度，并将每条发现的门禁标注为 BLOCKING（未达 AA 目标，或使游戏关键信息仅存在于单一通道）或 ADVISORY — 门禁列绝不使用 HIGH 之类的严重程度词
- 不重新设计 HUD — 产出发现供 ux-designer 和 ui-programmer 处理

### 用例 2：领域外请求 — 正确重定向
**输入：**"设计整体游戏流程：主菜单 → 角色选择 → 加载 → 游戏 → 暂停 → 结算。"
**预期行为：**
- 不产出 UX 流程架构 — 流程设计不在其核心职责内（审查、标准、输入审查、文本可读性、色彩安全、辅助功能建议），且项目协作规则禁止 Agent 在其领域外做约束性决策
- 明确说明整体游戏流程设计属于 `ux-designer` — 即其协作部分为交互模式指定的伙伴
- 将请求重定向至 `ux-designer`
- 其替代流程提供的任何内容均来自自身领域 — 例如流程设计完成后对其进行无障碍审查（SC 2.2.1 计时可调下的时间限制、其认知无障碍规则如随时可暂停）— 绝不提供流程架构

### 用例 3：色盲模式冲突
**输入：**"针对绿色盲的拟议色盲模式将敌方红色血条替换为橙色，但美术调色板已用橙色表示友方单位。"
**预期行为：**
- 识别冲突：色盲模式与既有友方单位调色板之间的橙色碰撞
- 不单方面更改美术调色板（该权限属于 art-director）
- 向 `art-director` 报告冲突，描述具体的视觉重叠
- 提出无需更改调色板的替代区分策略（例如形状/图标叠加、图案填充、图标化）

### 用例 4：无障碍功能的 UI 状态需求
**输入：**"物品栏的屏幕阅读器支持要求系统将物品名称和数量暴露为可访问文本节点。"
**预期行为：**
- 定义需求（其核心职责："定义并执行无障碍标准"）：为每个物品栏元素（槽位、物品、数量、空槽位）定义屏幕阅读器必须播报的可访问名称和值
- 按其 WCAG 引用规则，以编号和简称引用适用准则（例如 SC 4.1.2 名称、角色、值；SC 1.3.1 信息与关系）
- 识别实现可访问文本节点需要 UI 系统变更
- 将实现交给 `ui-programmer` — 即其协作部分指定的 UI 实现者 — 而非自行承担
- 不自行实现 UI 系统变更

### 用例 5：上下文传递 — WCAG 2.1 目标
**输入：**上下文中提供的项目无障碍目标：WCAG 2.1 AA 合规。请求："审查对话系统的无障碍性。"
**预期行为：**
- 引用与对话相关的具体 WCAG 2.1 AA 成功准则（例如 1.4.3 对比度最低要求、1.4.4 调整文本大小、2.2.1 计时可调用于自动推进对话）
- 使用标准中的精确准则编号和名称，而非转述
- 为每条发现标注其未通过的具体准则
- 同时检查自身的对话规则：带说话人标识的字幕、至少 3 种字幕大小选项
- 不将仅 AAA 的准则（例如 SC 1.4.6 对比度（增强）7:1、SC 2.2.3 无计时）报告为未达 AA 目标；若提及，标注为 AAA 且超出既定目标，门禁为 ADVISORY

## 协议合规

- [ ] 保持在声明的领域内（重映射、文本缩放、色盲模式、屏幕阅读器、标准合规）
- [ ] 将整体流程设计重定向至 ux-designer，将美术调色板决策重定向至 art-director — 即其协作部分为这些领域指定的伙伴
- [ ] 返回包含具体元素名称、对比度和准则引用的结构化发现
- [ ] 不实现 UI 变更 — 与 ui-programmer 协调实现
- [ ] 提供合规目标时按编号引用具体 WCAG 准则
- [ ] 向 art-director 报告无障碍要求与美术决策之间的冲突
- [ ] 在写入任何审查或需求文档前，询问"我可以将此写入 [文件路径] 吗？"并指明文件（例如 `production/qa/accessibility/[screen-or-feature]-audit-[date].md`）

## 覆盖说明
- HUD 审查（用例 1）应产出可在冲刺待办中作为无障碍故事跟踪的发现
- 色盲冲突（用例 3）确认 Agent 尊重 art-director 对调色板的权限
- WCAG 准则（用例 5）验证 Agent 精确而非笼统地使用标准
