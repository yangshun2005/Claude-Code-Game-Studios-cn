# Agent 测试规范：art-director

## Agent 摘要
**负责领域：** 视觉识别、美术圣经的撰写与执行、资产质量标准、UI/UX 视觉设计、视觉阶段门禁、概念美术评估。
**不负责：** UX 交互流程与信息架构（ux-designer 的领域）、音频方向（audio-director）、代码实现。
**处理的 Gate ID：** AD-CONCEPT-VISUAL、AD-ART-BIBLE、AD-VISUAL、AD-PHASE-GATE。

---

## 静态断言（结构性）

通过读取 agent 的 `.claude/agents/art-director.md` frontmatter 验证：

- [ ] `description:` 字段存在且领域明确（提及视觉识别、美术圣经、资产标准——而非泛泛而谈）
- [ ] `tools:` 包含 Read（同时可打开图片进行视觉审查）以及用于维护美术圣经的 Write/Edit，且不含 Bash——`disallowedTools:` 将其屏蔽
- [ ] 模型层级为 `inherit`——frontmatter 的 `model:` 精确为 `inherit`（层级说明见 `.claude/docs/model-tiers.md`）
- [ ] Agent 定义未声称对 UX 交互流程或音频方向拥有权限

## 测试用例

### 用例 1：领域内请求——输出格式恰当
**场景：** 提交一份完整的美术圣经进行签核，包含支柱与核心幻想、平台约束以及头脑风暴阶段选定的视觉识别锚点。其色彩部分定义了低饱和大地色主色调，并配有与游戏支柱"衰败之美"绑定的高对比强调色；其形状语言、资产标准和角色方向与该部分一致，且处于所述平台约束之内。请求标记为 AD-ART-BIBLE。
**预期：** 返回 `AD-ART-BIBLE: APPROVE`，理由需确认调色板的内部一致性，以及色彩系统符合该支柱的情绪目标。
**断言：**
- [ ] 结论恰为 APPROVE / CONCERNS / REJECT 之一
- [ ] 结论标记格式为 `AD-ART-BIBLE: APPROVE`
- [ ] 理由引用具体的调色板特征及其如何服务于"衰败之美"情绪目标（即该门禁的色彩与情绪检查）——而非泛泛的美术建议
- [ ] 输出保持在视觉领域内——不评论 UX 交互模式或音频情绪

### 用例 2：领域外请求——重定向或上报
**场景：** 音效设计师要求 art-director 规定玩家进入战斗区域时环境音频应如何分层与闪避（duck）。
**预期：** Agent 拒绝定义音频行为，并重定向至 audio-director。
**断言：**
- [ ] 不对音频分层或闪避行为做出任何有约束力的决定
- [ ] 明确点名 `audio-director` 为正确处理者
- [ ] 其任何评论仅涉及该区域的视觉情绪（例如"音频应匹配该区域的视觉张力"）——不指定任何层、闪避量、淡入时间或触发条件

### 用例 3：门禁结论——词汇正确
**场景：** 支柱刚锁定后，提交概念与支柱集合以确定视觉识别锚点。三个支柱为"有趣的战斗""精彩的故事""大量内容"；它们的设计测试均未提及情绪、氛围或世界应有的感觉，也未给出任何视觉参照。请求标记为 AD-CONCEPT-VISUAL。
**预期：** 返回 `AD-CONCEPT-VISUAL: CONCERNS`——这是该门禁对尚不足以区分视觉识别的支柱所给的结论——点名哪些支柱未给出视觉方向，以及缺失了什么（情绪、形状语言、色彩含义）。
**断言：**
- [ ] 结论恰为 CONCEPTS / STRONG / CONCERNS 之一（AD-CONCEPT-VISUAL 的结论词汇）——而非 APPROVE / REJECT，也非自由文本
- [ ] 结论标记格式为 `AD-CONCEPT-VISUAL: CONCERNS`
- [ ] 理由点名未给出视觉方向的具体支柱，以及它们未明确该门禁四个方向组件（视觉规则、情绪、形状语言、色彩哲学）中的哪些——而非泛泛的"支柱含糊"
- [ ] 不自行改写支柱——支柱变更需退回用户与 creative-director

### 用例 4：冲突上报——正确的上级
**场景：** ux-designer 提议 HUD 使用高对比、色彩鲜艳的图标以提升可读性。art-director 认为这违反美术圣经的柔和视觉语言，会损害视觉识别。
**预期：** art-director 陈述视觉识别方面的顾虑并引用美术圣经，承认 ux-designer 的可读性目标合理，并上报至 creative-director 裁决视觉一致性与可用性之间的权衡。
**断言：**
- [ ] 上报至 `creative-director`（创意领域冲突的共同上级）
- [ ] 不单方面推翻 ux-designer 的可读性建议
- [ ] 清晰地将冲突框定为两个合理目标之间的权衡
- [ ] 引用被违反的具体美术圣经规则

### 用例 5：上下文传递——使用提供的上下文
**场景：** Agent 收到一个门禁上下文块，其中包含现有美术圣经，带有具体调色板值（主色：#8B7355、#6B6B47；强调色：#C8A96E）和风格规则（"不用纯白、不用纯黑；所有阴影带暖色调"）。提交一种新资产类型供审查：首个敌人精灵图集，其身体颜色取自主色板，但轮廓为纯黑（#000000）、高光为纯白（#FFFFFF）、阴影为冷蓝灰（#5A6A7A）。请求标记为 AD-VISUAL。
**预期：** 评估引用所提供美术圣经中的具体十六进制值和风格规则，而非泛泛的色彩理论建议，并返回 `AD-VISUAL: REJECT`——该精灵图违反全部三条风格规则，属使用该资产类型前须解决的风格违规——每项违规均对应其所违反的规则。
**断言：**
- [ ] 引用所提供美术圣经上下文中的具体调色板值
- [ ] 应用所提供文档中的具体风格规则（不用纯白/纯黑、阴影带暖色调），点名违反这些规则的轮廓、高光和阴影颜色
- [ ] 不生成与所提供美术圣经脱节的泛泛美术方向反馈
- [ ] 结论标记为 `AD-VISUAL: REJECT`，理由可追溯至所提供上下文中的具体行或规则

### 用例 6：门禁输入缺失——NOT ASSESSED
**场景：** 提交一份完整、内部一致的美术圣经进行签核，包含支柱和视觉识别锚点，但无平台或性能约束：上下文未提供，`project.yaml` 未设置任何 `platform.*` 或 `performance.*` 键，且 `.claude/docs/technical-preferences.md` 仍只含未配置的占位符。请求标记为 AD-ART-BIBLE。
**预期：** 返回 `AD-ART-BIBLE: NOT ASSESSED`，点名平台和性能约束为其无法读取的输入——缺少这些，该门禁关于资产标准在平台上可实现的检查无法进行。
**断言：**
- [ ] 结论标记为 `AD-ART-BIBLE: NOT ASSESSED`——而非 APPROVE，尽管其能检查的每个部分均无问题
- [ ] 点名平台和性能约束为缺失输入
- [ ] 不假设某个平台或预算以完成审查

## 协议合规

- [ ] 返回所调用门禁定义文件列出的结论词汇——AD-ART-BIBLE 和 AD-VISUAL 为 APPROVE / CONCERNS / REJECT；AD-CONCEPT-VISUAL 为 CONCEPTS / STRONG / CONCERNS；AD-PHASE-GATE 为 READY / CONCERNS / NOT READY；任何门禁在缺少其点名的输入时返回 `NOT ASSESSED` 并点名该输入
- [ ] 保持在声明的视觉领域内
- [ ] 将 UX 与视觉的冲突上报至 creative-director
- [ ] 输出中使用 Gate ID（例如 `AD-ART-BIBLE: APPROVE`），而非内联散文式结论
- [ ] 不对 UX 交互、音频或代码实现做出有约束力的决定
- [ ] 在阶段门禁中，将目标阶段需要、而调用技能传为"none"的构建产物视为一项发现（NOT READY 或 CONCERNS），将传为"在 [阶段] 之前不预期"或"在 `workflow: [tier]` 下不需要"的视为无发现——它评判的是即将进入阶段的就绪度，而非后续阶段
