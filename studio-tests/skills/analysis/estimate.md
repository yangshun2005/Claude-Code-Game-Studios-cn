# 技能测试规范：/estimate

## 技能摘要

`/estimate [task-description]` 估算单个任务的工作量。它从参数中读取任务描述（若描述过于模糊无法估算，先请求澄清），从 `CLAUDE.md` 读取项目上下文，从 `design/gdd/` 读取相关 GDD（阶段 1）。它扫描受影响的代码以评估复杂度、集成点和测试覆盖率，并读取 `production/sprints/` 中类似的已完成任务和历史速度（阶段 2）。它分析代码复杂度、范围和风险（阶段 3），然后输出估算（阶段 4）：复杂度评估表、乐观/预期/悲观三种场景的工作量估算（以天为单位）、等于预期值的建议预算、高/中/低置信度及其驱动因素、风险因素、依赖项、带总计的建议拆分，以及备注与假设——随后是一行摘要和 `Verdict: COMPLETE — estimate generated.`。估算值四舍五入到半天。该技能为只读，不调用任何总监门禁。

---

## 静态断言（结构性）

由 `/skill-test spec` 对照 SKILL.md 检查——无需夹具。

- [ ] 具有必需的 frontmatter 字段：`name`、`description`、`argument-hint`、`user-invocable`、`allowed-tools`
- [ ] 具有 ≥2 个阶段标题
- [ ] 包含乐观/预期/悲观场景、高/中/低置信度级别以及 `COMPLETE` 判定
- [ ] 不要求"May I write"措辞（只读；声明不写入任何文件）
- [ ] 具有下一步交接（如何在冲刺规划中使用该估算）

---

## 总监门禁检查

无。估算是咨询性信息技能；不调用任何门禁。

---

## 夹具默认值

每个用例的 `project.yaml` 均设置 `modes.rigor: minimal` 和 `modes.automation: collaborative`，且无 `project.local.yaml`，除非其自身夹具另有说明。规则：`studio-tests/CLAUDE.md` § 夹具默认值。

## 测试用例

### 用例 1：正常路径——在有文档记录且存在现有模式的系统中执行明确任务

**夹具：**
- `project.yaml`：`engine.name: godot`，因此代码根目录为 `src/`
- `design/gdd/combat.md` 记录了近战命中检测
- `src/combat/` 包含近战攻击代码；其中已有类似的碰撞代码
- `production/sprints/sprint-003.md` 至 `sprint-005.md` 记录了已完成的战斗任务

**输入：** `/estimate Add hitbox detection to melee attacks`

**预期行为：**
1. 技能复述任务；描述足够具体，因此不请求澄清
2. 技能读取 `design/gdd/combat.md`，因为任务涉及有文档记录的系统
3. 技能扫描 `src/combat/` 以查找受影响文件、集成点和现有测试
4. 技能读取 `production/sprints/` 以查找类似的已完成任务和速度
5. 输出遵循阶段 4 模板：复杂度评估、工作量估算（乐观/预期/悲观，以天为单位）、建议预算、置信度、风险因素、依赖项、带总计的建议拆分、备注与假设
6. 建议预算等于预期值；所有数值均为半天增量
7. 简要摘要给出建议预算、置信度级别和最大单一风险
8. 输出以 `Verdict: COMPLETE — estimate generated.` 结尾；不写入任何文件

**断言：**
- [ ] 在生成估算之前读取了战斗 GDD 和冲刺历史
- [ ] 复杂度评估的规模行给出受影响文件的 Grep 计数（非空行、分支行），并称分支为近似值而非实测复杂度
- [ ] 工作量以三个天数（乐观、预期、悲观）给出，而非单一数字
- [ ] 建议预算等于预期值，而非乐观值
- [ ] 数值四舍五入到半天，而非小时
- [ ] 结尾摘要列出预算、置信度和最大风险
- [ ] 不写入任何文件

### 用例 2：高不确定性——新子系统，架构未定

**夹具：**
- `project.yaml`：`engine.name: godot`
- `src/` 中没有任何在线或匹配子系统的源文件
- `design/gdd/online.md` 描述了大厅，需求标注为"TBD"，并说明网络方案（传输、主机模型）尚未决定

**输入：** `/estimate Implement online lobby matchmaking`

**预期行为：**
1. 技能读取 `design/gdd/online.md`，发现未解决的需求和未定的网络方案
2. 代码扫描未发现现有子系统；"现有模式可用"为否
3. 风险因素表列出具体未知项：GDD 未决定的网络方案、新技术、不明确的需求
4. 置信度为低，并解释驱动因素
5. 阶段 5 建议在承诺前通过 `/prototype` 进行限时探索
6. 不写入任何文件

**断言：**
- [ ] 当任务方案未定、无现有代码且需求为 TBD 时，置信度为低
- [ ] 风险因素表列出驱动不确定性的具体未知项
- [ ] 输出建议在承诺前进行限时 `/prototype` 探索
- [ ] 不写入任何文件

---

### 用例 3：无冲刺速度数据——仍生成估算，并说明缺口

**夹具：**
- `project.yaml`：`engine.name: godot`；`src/core/` 包含存档涉及的库存代码
- `design/gdd/save-load.md` 清晰记录了存档系统
- `production/sprints/` 为空——无历史冲刺

**输入：** `/estimate Implement save and load of player inventory`

**预期行为：**
1. 技能读取任务、GDD 和受影响代码
2. 技能查找过往冲刺数据，未找到
3. 仍生成包含全部三种场景和建议预算的估算
4. 备注与假设（或置信度说明）声明无冲刺历史可用，因此数值未按团队速度校准
5. 不静默填充任何数值来弥补缺失数据——任何额外风险均明确说明
6. 不写入任何文件

**断言：**
- [ ] 无冲刺历史时技能不报错或停止
- [ ] 仍生成包含乐观、预期和悲观数值的估算
- [ ] 输出声明无冲刺历史可用于速度校准
- [ ] 对缺失数据的任何补偿均作为风险说明，而非隐藏在数值中

---

### 用例 4：模糊任务——估算前先澄清

**夹具：**
- `project.yaml`：`engine.name: godot`
- 项目在 `src/` 下有 GDD 和源代码；存在冲刺历史

**输入：** `/estimate make combat feel better`

**预期行为：**
1. 技能读取任务描述，发现其过于模糊无法有意义地估算（无范围、未指明变更）
2. 技能在继续前请求澄清
3. 在任务澄清前不生成复杂度评估、工作量估算或判定
4. 不写入任何文件

**断言：**
- [ ] 对于未指明具体变更的任务，技能请求澄清
- [ ] 在澄清得到答复前不生成任何估算数值
- [ ] 对于未澄清的任务不打印 `Verdict: COMPLETE`
- [ ] 不写入任何文件

---

### 用例 5：门禁合规——无门禁；估算为信息性

**夹具：**
- `project.yaml`：`engine.name: godot`，`modes.review_mode: full`
- 任务涉及有文档记录的中等复杂度系统；其代码位于 `src/` 下

**输入：** `/estimate Add item pickup with inventory stacking`

**预期行为：**
1. 技能读取上下文、扫描代码和冲刺历史；生成估算
2. 在任何审查模式下均不调用总监门禁
3. 估算仅作为咨询性输出呈现
4. 下一步包括"运行 `/sprint-plan update` 将其加入下一冲刺"

**断言：**
- [ ] 无论审查模式如何均不调用总监门禁
- [ ] 输出纯为信息性——无批准或写入提示
- [ ] 下一步建议引用 `/sprint-plan`
- [ ] 估算不因审查模式而改变

## 协议合规

- [ ] 在估算前读取任务参数、项目上下文和任何相关 GDD
- [ ] 在可用时读取 `production/sprints/` 以查找类似任务和速度
- [ ] 生成工作量范围（乐观/预期/悲观天数），而非单一数字
- [ ] 不写入任何文件
- [ ] 不调用任何总监门禁
- [ ] 以阶段 5 的下一步结尾，并与结果匹配（低置信度用 `/prototype`，超过 10 天的任务用 `/create-stories`，安排用 `/sprint-plan update`）

---

## 覆盖说明

- 该技能每次运行估算一个任务；包含多个故事的冲刺文件不是支持的输入。
- "任务超过 10 天 → 通过 `/create-stories` 拆分为更小的故事"分支没有单独用例。
- 天数数值的准确性取决于团队，不做测试；断言检查范围的结构、来源和声明的驱动因素。
